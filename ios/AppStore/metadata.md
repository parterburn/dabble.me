## App Privacy ("nutrition label")

Data used to track you: **none**. Data linked to you, all for **App Functionality** only:

| Data type | Why |
|---|---|
| Contact Info → Email Address | Account identity and sign-in |
| User Content → Other User Content | Journal entries |
| User Content → Photos or Videos | Photos attached to entries |
| Identifiers → User ID | Account identity |

The app has no analytics or crash SDKs, and these answers match `DabbleMe/Resources/PrivacyInfo.xcprivacy`. Not collected: Apple Intelligence features run on the device; the calendar's events are read on the device to list them while writing and are sent nowhere (only one the writer taps goes into their entry); reminders (with the past entries they'll show), the Face ID setting, the entry template and drafts stay on the device; Share hands an entry to iOS's share sheet only when the writer asks; the widget reads whether today is written, the day's prompt and (only with Show Entry Previews on in Settings → Home Screen Widget) the start of one entry and a small copy of its photo, which the app stores in its App Group on the device.

## Decisions

- **In-app purchase (from build 116):** PRO Monthly (`me.dabble.ios.pro.monthly`) and PRO Yearly (`me.dabble.ios.pro.yearly`), one subscription group, StoreKit 2 (`SubscriptionStore`, `SubscribeOptions`, `PlanView`). Each purchase carries the account's `appAccountToken`; the server verifies it with Apple before PRO turns on (`AppStore` in `app/lib`). The free-companion-app route (guideline 3.1.3(f)) no longer applies once the app sells something. The app links nowhere to buy PRO outside it (Paul removed the US-only dabble.me/subscribe link on 2026-11-27); accounts that bought PRO on the web are still PRO in the app. Family Sharing is off. A free trial is an introductory offer set in App Store Connect (2 weeks suggested); the app shows it only to Apple Accounts still eligible, and records no payment for it.
- **Free vs PRO in the app:** (the editor's Photos button shows for free accounts and says photos come with PRO) free accounts read, write and delete text entries, use the on-device Apple Intelligence features (reflections, Today's prompt, hashtag suggestions), keep an entry template, see the day's calendar events while writing, share an entry, set the daily reminder (which can bring a past entry), and see the Photos view, Songs and the widget; photos, links, editing, search (and its hashtag cloud), Stats (and the year in review at the top of it), On This Day, choosing the email's days, and AI connections are PRO. Dictation is the keyboard's own (no in-app mic). Face ID lock and drafts are for everyone.
- **Account deletion:** in the app (guideline 5.1.1(v)): Settings → Account → Delete Account shows the entry count, an export link and any billing to cancel elsewhere (Gumroad, PayPal, or an App Store subscription, which only the person can cancel, in iOS Settings), asks for the password (an emailed code for an account with no password, or a passkey) and confirms once more (`DeleteAccountView`, `/api/v1/account_deletion`). The app signs out; the account goes an hour later, as on the web, unless the person signs back in. A Stripe subscription is cancelled with it. No email step for password accounts.
- **Sign-in and sign-up:** the app's own form (`AuthFormView`; `/api/v1/session/code`, `/api/v1/session/code/verify`, `/api/v1/session`, `/api/v1/session/passkey`): an email, then a 6-digit emailed code (which creates the account when there isn't one; sign-up needs no password), or "Use Password Instead" on the code screen, plus the 2FA code when it's on, or a passkey (the site's own, via `webcredentials:dabble.me`). Sign in with Apple, if a third-party login is ever added, goes above the fields (guideline 4.8).
- **iPad:** supported from the first version, so the submission needs the 13" iPad screenshot set too.
